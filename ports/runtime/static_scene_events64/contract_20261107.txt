Static SDK event tape and explicit-entry matrix observations

j2p_static_scene_tape reads a mapped MDL0 model and emits owned SBC events, flat owned matrix64 commands and actual MAT shader-register deltas. j2p_static_scene_snapshots separately applies those matrix segments to an explicit caller entry state and records all four current matrices at every SHP reference. Neither API transforms vertices, binds texture banks, submits geometry or renders. Source and matching credit are zero.

J2pSceneOwner binds the complete host/ARM9/main mapping scope and nonzero mapping generation, model-set address, model index, bounded model-set length, nonzero instance identity, run generation, matrix generation, material generation and attribute generation. Seed, tape, entry and observations carry this identity. The caller must supply the actual current identity and advance the relevant generations when replacing source bytes, mappings, model instances or entry state. Reusing an obsolete identity after changing its referent violates the contract. The API has no process-global traversal or material cache.

All pointers designate live, correctly aligned objects of their declared C types and declared capacities. Source model bytes may be unaligned and are read bytewise. Every source mapping, input descriptor, seed and owned input array remains immutable for the complete call. The caller owns synchronization, lifetime and generation management; no implicit locking or async GPU synchronization is supplied. Header and full declared writable ranges must be disjoint from each other, input objects, the guest-space registry and every mapped guest region, including unrelated namespaces.

The seed explicitly declares a fresh callback-free SDK material context. provider_flags must be zero; any nonzero provider flag refuses the entire transaction with -2. No callback, animation, externally recorded material result or preexisting SDK material cache can be imported. shader_valid must equal 31 and supplies all five initial pending MAT register values in opcode order 30,31,29,2A,2B. The three material_defaults words are the explicit SDK global color0, color1 and polygon defaults. These words do not seed coordinate, vertex-color, UV, normal, primitive or current-polygon latches. Those require a separate complete entry state in a future streaming geometry consumer.

Count-only tape validation passes null work/output and commits only the validated header. Construction supplies separate planner scratch, stage command/event/shader arrays and output command/event/shader arrays. Capacities count typed records. A zero-capacity buffer must be null. Nonzero capacities require nonnull live arrays. Matrix capacities are at most 10000; event and shader byte products must fit uint32. A complete source validation/count pass and all capacity/overlap checks precede any caller scratch/output write. A second deterministic pass stages records and commits the outputs and header. Under source/input immutability every refusal preserves all input, output and staging bytes.

The source profile is exactly the unchanged sealed static matrix planner: SBC type zero, rule-2 scaling and at most 64 nodes/materials; exact SBC bytes 01,02,04,24,44,05,06,26,46,66,0B,2B. SBC NOP00 is explicitly refused by that sealed planner even though the original SDK executes it. No event is normalized or silently dropped. Billboard, NODEMIX/skinning, CALLDL, explicit SBC matrix/camera/environment/projection commands, animation, unqualified providers and general SDK streams remain outside this component. Display-list NOP words remain admitted by the unchanged matrix-free wire framer. The existing planner's material mask3FFF, TEXMTX_USE-clear requirement, optional payload checks and source/shape bounds remain unchanged.

Every event retains the exact SBC offset, ordinal, opcode and length, contiguous matrix and shader spans, post-handler low-six SDK flags, current node/description/material validity, current six-word material result, two cache-valid words and pending MAT register parameters. Matrix commands are not reordered across MAT, NODE or SHP events. Initial material identity is UINT32_MAX with material_valid zero. SHP before MAT is retained and can be submitted by the SDK; it never becomes material zero. This API supplies no texture-bank fallback. Any later material/bank join must explicitly resolve or refuse that unbound state.

NODE visibility uses only the low bit of the source byte. Material indices31/32/63 use the actual two-word cache boundary. Cold MAT40 populates and validates its cache entry; cold MAT00/20 uses a temporary result, so repeated20 alone does not create a cache hit. Warm20/40 reuses the valid cache entry. Invisible reuse of the same valid material skips evaluation and retains the old gate/result; a different material is still evaluated. Nonzero alpha is tested before wireframe alpha clearing. Consequently an initially opaque wireframe use emits registers and permits submission even though its resulting polygon alpha becomes zero; a later cached use can set the SDK transparency gate. These are SDK decisions, distinct from renderer visibility or rasterization.

Shader records contain only actual emitted MAT deltas, in original order 30,31,29,2A,2B. shader_state names the five last pending MAT register parameters, not a complete current GPU state. No MAT is re-emitted at SHP. COLOR can change vertex color after register30, register29 changes pending polygon attributes while BEGIN40 latches current polygon attributes, and UV/partial coordinates/open primitives can persist across submitted display lists. A future streaming consumer must preserve these uninterrupted latches. Skipped SHP lists must not advance that consumer. This event layer does not reconstruct those latches.

SHP references and actual submissions have separate monotonically increasing ordinals. submission1 means the callback-free SDK submits the bounded display list, submission2 means source visibility suppressed it, and submission3 means the SDK transparency gate suppressed it. Unsupported state is an API failure, never a fourth skipped-draw status. Both submitted and skipped references retain shape index/address and display-list address/length. Source identity stays bound to the selected model and source SBC offset; emitted-draw or scene-equivalence credit is not inferred from a referenced shape.

Snapshot construction requires a distinct J2pSceneEntry containing the complete owned matrix64 state, including explicit current matrices and initialized dual stacks. Its entry mode and the plan requirement must both be2. There is no implicit seed, identity operation or state advance. The function validates the entire event/command sequence and replays it locally before touching snapshot staging/output. It then stages one observation for every SHP reference at that reference's matrix prefix and commits the final separate entry-state output. Using a model's final matrix for all shapes is incorrect. Matrix64 retains checked whole-dot floor12/narrow/add bounds, slot31 and uninitialized-restore refusals, and whole-transaction arithmetic failure. No transformed positions or screen/world coordinates are produced.

Success is1. Invalid identities, layouts, pointers, overlap or structural input return-1; unsupported feature/provider/event profiles return-2; inherited node-dependency/duplication failures can return-3; inherited matrix arithmetic refusals return-4; insufficient capacities or the matrix-command bound return-5. The immutable tape/command/event arrays are caller-owned records produced by this API, not an authenticated serialization format. Their declared input lengths must designate actual live arrays. Snapshot structural checks do not establish source authenticity independently of the owner's lifetime contract.

Qualification separately invokes actual original SDK helpers and a Python event/material state machine. The unchanged matrix planner's8192-mask sweeps and37 matrix plus72 planner refusal policies remain preserved. The new reference executable links an untouched pinned melonDS core only in work, never in production. It resets once per reference sequence, explicitly seeds tested state, feeds one command at a time and drains via actual ExecuteCommand. Queues are empty between commands; the admitted table has at most16 parameters, well below pipe/FIFO capacity. A64-step drain bound is enforced; the observed maximum is12. No async scheduling, FIFO backpressure, hardware ready timing or actual device behavior is proved.

The reference preserves all four TempVertexBuffer records before and after every command, including all17 semantic fields per record. It independently checks the newly submitted record's preclip position/color/UV, matrices and persistent latches. Quad-strip fourth vertices move to slot2; observing only the old slot3 is wrong. FinalPosition, FinalColor, HiresPosition and clipping fields are preserved as observations but are not qualified screen/raster outputs. The core can internally execute polygon assembly, culling and clipping even with rasterization disabled. No DS hardware, camera, transformed-vertex production stage, skinning, billboards, animation, rendering, scene execution, Android device or game execution is claimed.
