Static matrix-command planning

j2p_static_matrix_plan(space, current_owner, model_bytes, scratch, scratch_capacity, output, output_capacity, header)

This reads one mapped MDL0 model and builds owned matrix64 commands in actual SBC order. It does not apply commands, create a matrix seed, transform vertices, interpret draw results, submit hardware work or render. Source and matching credit are zero. It requires the existing guest-memory, node-pose and matrix64 headers and implementations.

The owner is the full host/ARM9/main/nonzero-generation identity plus model-set address and selected model index. The mapping must remain live and immutable for the complete call. The caller owns synchronization and generation advancement and must supply the actual current owner, rather than reusing an obsolete identity after changing a mapping. Every pointer must designate a live, correctly aligned object of its declared C type; source bytes are parsed bytewise and may have unaligned host storage. No raw-byte struct overlays are used for source records.

model_bytes bounds the entire mapped model-set input. The selected model and all followed node, material, shape and display-list records must lie in that input and their declared selected-model spans. The header binds the owner, input length, selected model span, SBC span, required matrix mode and command count. No output argument contains a pointer into source bytes.

For count-only validation, pass null scratch/output and zero capacities. A successful call commits the complete header and count. For construction, supply separate caller-owned typed J2pMatrixCommand arrays for scratch and output, with each capacity between 1 and 10000 and at least the validated command count. Capacities count records, not bytes. The full declared buffers and header must be mutually disjoint and disjoint from the owner, guest-space registry and every mapped guest region, including unrelated scopes. Scratch is explicit to avoid a large implicit stack allocation or hidden allocator.

Construction first validates the entire source and counts commands without touching caller output or scratch. After checking capacities it repeats the deterministic traversal into scratch, then commits the command array and header. Source, registry and owner immutability are caller preconditions during both traversals and between an optional query and build. Under those preconditions every refusal leaves header, scratch, output and all inputs unchanged. Successful construction writes only the first command_count records in each array. No persistent traversal cursor or process-global model/material state is imported or advanced.

Every plan requires entry matrix mode 2. The caller must initialize an explicit J2pMatrixSeed and state, check state.mode == header.required_mode, check header/current/state ownership, then separately call j2p_matrix_apply with exactly header.command_count commands. The planner does not insert MODE or IDENTITY operations. Matrix64 intentionally supports other modes for other callers and does not accept this plan header as an argument; honoring the plan's entry-mode precondition is the caller's responsibility. Matrix64 performs separate whole-batch stack and arithmetic admission and can refuse a correctly framed plan without changing state. Uninitialized restores cannot be decided by source planning without the caller's entry state.

The source profile is SBC type 0 and scaling rule 2 through the existing node-pose API, including its 64-node ownership/dependency rules. Supported exact SBC bytes are 01,02,04,24,44,05,06,26,46,66,0B,2B. Other variants, NOP/explicit SBC matrix commands outside the sealed node-pose API, billboard, skin/NODEMIX, CALLDL and camera/env/projection operations remain outside this profile. NODEDESC metadata bytes are not hardcoded to zero; visibility bytes are not hardcoded to one. Those fields do not change matrix emission through the qualified callback-free rule-2 path. Optional restore precedes local sender operations, and optional store follows them. Stack indices 0..30 are supported; 31 is refused.

POSSCALE uses model offsets +28/+32, independently established by the actual original initializer and consumers. Inherited translation uses signed64 products, floor division by 4096, then signed low-32-bit wrapping through the qualified node-pose helper. It does not saturate or refuse a source value merely because the shifted intermediate exceeds signed32. The resulting commands are still subject to matrix64's separate checked arithmetic bounds. Rotation[9] and translation[3] are copied separately into owned command arguments.

Each referenced tag-0 material is validated afresh. The documented flag mask is 3FFF and TEXMTX_USE bit0001 must be clear; unknown C000 bits are a port-policy refusal. No hardcoded 1FCE value is required. Declared optional effect-matrix payloads must fit their record. The callback-free original handler has no matrix effects under this feature mask with a fresh cache or the same immutable material generation. This planner accepts no callback, animation or recorded-material providers and imports no external material cache. EFFECTMTX2000 alone is inert through MAT; separate environment/projection SBC operations remain refused.

Matrix-free materials still have shading and cache/transparency effects. In particular, cached wireframe alpha clearing can make a later use transparent. This planner does not export or qualify draw-state equivalence, material rendering, shape visibility or bank associations. Those belong to separate resource/draw APIs and future consumers.

Each referenced tag-0 shape has a bounded nonempty display list of at least four bytes. The actual original submission helper dereferences and emits a first word even for a declared zero-byte list, so zero cannot establish a bounded original transfer. Word alignment, source offset/length bounds, explicit opcode support and complete parameter spans are required.

The display-list validator is matrix-free wire framing only. Admitted opcodes and parameter-word counts are 00:0,20:1,22:1,23:2,24:1,25:1,26:1,27:1,40:1,41:0. Opcode28 VTX_DIFF is outside the qualified command domain. 25/26/27 are XY/XZ/YZ partial-coordinate commands. NOP padding is supported. Unknown opcodes, hidden matrix commands and truncated parameters are refused, including errors at the end of a list.

No coordinate-latch or self-contained primitive policy is imposed. Partial-first vertices, inherited/open primitive state, END-only and incomplete primitive groups can be framed without reconstructing coordinates. Admission does not prove mesh validity, hardware completion or timing for such streams. Original SDK submissions and independent pinned-core FIFO ingress were checked without executing vertex or rasterization commands. The existing geometry decoder remains unchanged and can have narrower coordinate-context requirements; this planner does not expand that API's domain.

Success returns 1. Invalid identity, pointers, overlap, source bounds or capacities return -1; unsupported source features return -2; node dependency/duplication failures can return -3; insufficient buffers or more than 10000 commands return -5. Matrix64's later -4 arithmetic refusal and uninitialized-stack refusal remain distinct. A valid zero-command source plan is supported even though referenced shape transfers must be nonempty.

All qualification receipts distinguish source commands from explicit test seed setup. Actual DS hardware timing, asynchronous DMA, FIFO backpressure, readback/camera state, GPU overflow outside admitted arithmetic, transformed geometry, animation, skinning, billboards, rendering, device execution and complete game execution remain unproven. The static component does not establish overall native completion.
