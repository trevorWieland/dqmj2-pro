# Native G3D asset pipeline

This standalone C11 library connects real file-backed NitroFS reads, the recovered resource loader, BMD/BTX block framing, canonical MDL0 material associations and TEX0 pixel decoding. It produces caller-owned RGBA bytes. It supplies no renderer, VRAM upload, scene execution or playable game.

The [CMake source list](CMakeLists.txt) compiles 25 frozen C inputs directly plus the new duplicate-policy entry point. It has no runtime dependency on another qualification library. It selects `nitrofs_resource_bridge_20261106.c` exclusively; the alternative `resource_bridge_20261106.c` must not be linked alongside it. Existing DS sources, other standalone projects and matching credit remain unchanged.

Use CMake 3.22+, Ninja, Python 3 and Clang or GCC. Windows is qualified with LLVM-MinGW:

```text
cmake -S ports/native-g3d-assets -B work/native-g3d-assets/windows-release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build work/native-g3d-assets/windows-release
ctest --test-dir work/native-g3d-assets/windows-release --output-on-failure
```

Pass `-DCMAKE_C_COMPILER=/path/to/clang` when needed. Repeat in a separate directory with `-DCMAKE_BUILD_TYPE=Debug`. Strict C11 and aliasing checks remain enabled. The target preserves two existing signed-comparison warning suppressions for qualified filesystem views.

```text
cmake -S ports/native-g3d-assets -B work/native-g3d-assets/android-arm64 -G Ninja -DCMAKE_TOOLCHAIN_FILE=/path/to/ndk/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-33 -DANDROID_STL=none -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build work/native-g3d-assets/android-arm64
python ports/native-storage/check_android_elf.py work/native-g3d-assets/android-arm64/libj2p_native_g3d_assets.so
```

Android requires resolved symbols and 16 KiB LOAD alignment. Linking establishes no Android or AYN Thor execution.

## Synthetic host test

`test_assets.py` uses only the Python standard library and locally generated bytes. It mounts 24 synthetic NDS images, loads each model and two texture banks through the actual file/card and allocation chain, resolves their BMD/BTX blocks and decodes 1,224 material associations. Fixtures contain two models with 1, 3, 16 or 31 materials and independently permuted texture/palette mappings. Both banks deliberately expose identical names with different colors, making resource-bank choice explicit.

Known RGBA patterns cover I4, I8, all four compressed-4x4 modes, RGB555 palette words, indexed color0 transparency and nonpremultiplied output. Expected interpolation colors are explicit numeric values. Namespace/generation mismatches, malformed model and texture extents, bad material indices, missing dictionaries, unsupported formats, insufficient capacity, input/output overlap, duplicate bindings and malformed FNT/FAT offsets preserve output bytes. Source payloads and guard bytes remain unchanged.

No game inputs, private manifests, original ARM bytes, interpreter, ndspy dependency, downloaded asset or private golden file is used. Separate owner-private original-code qualification established the frozen parser/binder domain; that evidence is not required to build or run this public suite.

## API contract

Use `j2p_g3d_assets_rgba` from [assets_policy.h](assets_policy.h) for the guarded decode path. Mount and resource APIs are declared in the selected runtime headers. Pass a mapped MDL0 model-set span, an explicitly chosen TEX0 bank span, model/material indices, an independently owned RGBA byte buffer and distinct native `uint32_t` width/height objects.

Return values are `1` success, `0` absent material/resource, `-1` invalid bounds/namespace, `-2` unsupported texture format and `-3` repeated selected-material binding. Width/height become zero on normal failure and RGBA output remains unchanged. The new guard rejects repeated selected-material indices within either complete binding list before decoding, including repeated identical indices. This is a port policy: it does not claim the original SDK rejected contradictory lists. The frozen low-level resolver remains available but has its previously qualified unambiguous-input domain.

The guard first obtains a successful result from the frozen bounded resolver, then reads those same immutable, validated fields to count bindings. Source mappings must not change between these steps. Both source resources must remain live for every operation. Caller-owned external serialization covers mappings, generation changes, resource providers, original SDK globals and shared Windows file handles. Active-call guards provide no synchronization.

Scope is HOST/ARM9/MAIN with a nonzero current generation. All native pointers must denote correctly typed live objects or complete byte objects of their stated sizes. Width/height objects cannot alias each other, source mappings, output or provider state. Output cannot overlap either resource. Returned guest addresses borrow their original scope/generation and mappings.

RGBA rows run top to bottom. Formats 3, 4 and 5 are supported; dimensions are powers of two from 8 through 1024, with compressed textures limited to 524,288 pixels. RGB555 expands by bit replication; palette bit15 is ignored. I4 uses low nibble first. Indexed color0 transparency preserves its palette RGB. Compressed modes interpolate in five-bit components before expansion and use transparent black where specified. Output is straight RGBA8.

Resource-bank selection stays caller-owned. This target does not establish the gameplay code that chooses a bank, texture animation, scene geometry, current-directory state, other archives, asynchronous filesystem scheduling, graphics commands, input, audio or device execution. All new derivative port code receives zero DS matching/source-acceptance credit.
