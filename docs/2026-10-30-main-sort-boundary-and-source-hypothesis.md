# Main heap-sort source and boundary review

Main ARM 0x0201D470 has a legacy configured extent of 348 bytes, followed by a separately configured eight-byte entry at 0x0201D5CC. The latter adds 16 to SP and pops the saved register set and PC. The normal entry creates that frame. The two tail instructions are unreachable from normal entry in the static instruction graph; the preceding instruction unconditionally branches back into the sorting loop. This supports retaining the tail as a compiler-owned fragment within a 356-byte function. It does not independently qualify the tail as a normal callable function.

The first pointer-corrected M2C hypothesis compiled to 356 bytes but matched only 156 same-offset bytes. Compiler-profile, declaration-order, block-order, loop-shape and counter-placement experiments remain recorded as negative and intermediate evidence. The final candidate uses ordinary C, readable variable names, a natural inner loop and a counter decrement after the first byte store. It contains no inline assembly, instruction arrays, volatile ordering or forced register assignments.

The final candidate now compiles to all 356 original bytes under the pinned 2.0/base compiler with O2/speed. Genuine MWLD also produces those exact 356 bytes without modifying the object or linked output. The legacy 348-byte acceptance request remains rejected. The working cohort 57 now uses an explicit 356-byte function declaration and preserves 0x0201D5CC as a named ARM label. The new source in `src/runtime/20261030_heap_sort/native_main_0201d470.c` passes the normal complete-boundary validator and genuine MWLD byte comparison. Cohort 57 now accepts the complete source as an actual module input. The eight-byte tail receives no independent function credit.

Run `python prove_main_heap_sort_exact_candidate_20261030.py` for the exact candidate. Its 191 native/source pairs require 382 actual returns, identical comparator traces, array writes and final records. Independent checks require sorted signed keys, record permutation, canaries, stack restoration and callee-saved registers. Counts are 0, 1, 2, 3, 5, 8 and 17; widths are 0, 1, 2, 4 and 7, with additional cases covering every signed-byte key. The compiled signed-byte comparator is caller-supplied test context and receives no game source credit. Invalid pointers, callback escape or nontermination, arbitrary game comparator effects and large or overflowing extents are unsupported.

Run `python review_main_heap_sort_boundary_20261030.py` for the separate boundary review. It decodes 89 ARM instructions, finds 87 reachable from normal entry under the normal callback-return assumption, and excludes the final two instructions from that reachable graph. No aligned immediate ARM branch or call in main targets the tail. No aligned pointer word in the initialized ARM9 module images targets its bytes in either address-bit representation. Unaligned pointers, computed targets, Thumb calls and nonstandard indirect continuations have not been universally excluded.

Evidence is in `evidence/functional/main-heap-sort-exact-candidate-20261030.json`, `evidence/attempts/main-heap-sort-exact-boundary-review-20261030.json` and the earlier named `main-heap-sort-*` experiment reports. The cohort 56 Git commit preserves the earlier nonmatching hypothesis and fixture. Its current runner reads the measured configured extent, retaining the same 382-return regression after the boundary correction. `boundary_reconciliations.py` updates only the two legacy candidate records through a hashed, versioned review; eight rejection controls cover namespace, input hash, historical evidence, gaps, invented extent, missing fragment and unlisted overlap errors. The original seed inventory is unchanged. The initial migration diagnostic accidentally compared ledger text with configuration text; it is retained, and the corrected report verifies the exact two-declaration change against the cohort 56 Git version. No source-only module or whole-ROM completion is claimed.

The corrected collector passes three equivalent-schema cases and a malformed-container rejection; the second full cohort run links the actual complete C object.
