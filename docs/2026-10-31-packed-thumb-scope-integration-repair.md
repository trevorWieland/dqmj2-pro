# Packed Thumb binding representation repair

The first cohort 91 module build failed before acceptance with `Inconsistent native symbol target: __binding_main_02096cf8_native_fn_02096cf8`. Standalone source/link/native/Windows proofs had passed. The failed driver, integration command/input snapshots, logs, registry, preferences and migration receipts are retained under cohort91-first-binding paths.

The newer packed classifier and six pointer-interface reports explicitly label their host-main symbols with scope `main`. The older reports leave that redundant map entry absent. Frozen `scoped_bindings` treats `(None, address)` and `(main, address)` as distinct and generates qualified aliases. Frozen `canonical_target` recognizes the ordinary native-function names for Thumb-bit normalization, while the generated aliases have another prefix. Merging the even entry address with its odd Thumb function-pointer value then fails. This is a measured report representation conflict, not a differing C or executable byte.

The narrow adapter handles exactly seven address-qualified host-main Thumb helpers: 02096CE8, 02096CF8, 02096D04, 02096D24, 02096D4C, 02096D6C and 02096D9C. It verifies the measured module hash, configured Thumb starts, function kind, names and explicit `nativeSymbolEntries` identity before omitting only their redundant `nativeSymbolModules` entries in two derived reports. All explicit module/mode evidence, original scopes, native targets, source/object hashes, match rows and isolated link proofs remain recorded. Other scope entries remain unchanged.

The adapter reproduces the original alias failure with the unchanged framework, then verifies the aligned representation merges even and odd Thumb views correctly. A separate worker model reproduces failure after 33 merges and passes all 65 targeted merges after the seven changes; ARM7, overlay and ARM-mode normalization negatives reject. Root independently replays that read-only model. No linker, matcher, source-selection rule, target mode, object, C source or frozen producer is changed. These checks add no source coverage.

Six new migration receipts point to the derived pointer report while retaining their earlier receipts and the original sources. The selected functions and object bytes are unchanged; the classifier remains one previously pending new source function. The repaired registry is accepted only after the complete module, regression and ROM gates pass. This writeup describes the repair and does not declare those gates passed.

Run `python adapt_packed_pointer_host_bindings_20261031.py` to regenerate the two derived reports through their unchanged original producers. `--existing` derives them from the current measured raw reports. The registered source seal additionally freezes all replay code and declared inputs. Run `python inspect_save_core_scope91_metadata_20261031.py` for the independent binding model. The repair transaction and its first unsuccessful metadata comparison are retained separately; the latter encountered a legacy row without a target-hash field and published no registry or preference changes.
