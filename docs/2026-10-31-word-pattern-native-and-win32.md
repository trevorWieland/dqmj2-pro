# Word pattern initialization: native and Win32 — 2026-10-31

Main ARM 0203C5B8/164 now reconstructs in ordinary C. The original retained draft passed a signed-word pointer plus four elements to its nonzero-mode fill path; the native instruction advances four bytes. The new source uses one element. An explicit value/destination/byte-count declaration for the fill call preserves the complete 164-byte compile and genuine link. No register attributes, executable bytes or linked-code patches appear in the source.

The measured prefix is a four-byte pointer at +0, signed count at +4 and byte mode at +8. A null argument chooses the global prefix at 020F5C00. For positive backed counts, mode zero fills preceding words with 1 and clears the final word; nonzero mode clears the first word and fills following words with 2. Nonpositive counts return zero and set the separate byte at 020F5BF0 to 1; positive counts return one and clear that byte. The names describe physical values and offsets, not a recovered game-object meaning or complete extent.

`python match_main_word_pattern_20261031.py` executes 602 deterministic original/source pairs: 1,204 actual caller returns and 1,168 separately observed returns from the original 76-byte fill body, with zero supplied helpers. All 256 mode bytes, explicit/default prefixes, selected counts 1..64 at loop boundaries and three nonpositive signed cases are exercised. All 156 caller instruction bytes and 76 fill instruction bytes are observed. Independent complete-buffer/flag models, unchanged prefix bytes, stack bounds, saved registers, full result registers/flags, return modes, read/write regions and actual termination are checked. Counts beyond the allocated range, unaligned/unbacked pointers and live writers remain unsupported.

The whole-C wrong-stride variant genuinely compiles/links at the original address but differs at one byte. Two original/wrong pairs actually return before checking independent models: one rejects the nonzero-mode corruption, one retains the zero-mode positive control. Their four caller and four helper returns are separate. The original fill body remains scaffolding and receives no reconstructed source or assembly credit.

`python check_main_word_pattern_windows32_20261031.py` compiles the unchanged recovered source into a native 32-bit Windows executable. PE machine 014C, PE32 format and a four-byte pointer assertion are verified. It really executes all 602 inputs on this machine, with 584 explicitly supplied C word-fill calls, and checks complete buffers, byte flags, both prefix canaries and returned values against original ARM golden hashes/results. Its binary receipt is checked independently by the parent process. A separately compiled wrong-stride executable returns normally from two source calls before reporting the first failed case. The count/receipt is not an emulator or full-game claim.

This test uses the hash-pinned local NDK clang/LLD plus newly measured LLVM dlltool. A local three-export import archive is generated from a text definition, with no SDK headers/import libraries or scratch-directory dependency. The own test process writes its 32-byte receipt through [GetStdHandle](https://learn.microsoft.com/en-us/windows/console/getstdhandle) and [WriteFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-writefile), then ends through [ExitProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-exitprocess). It starts hidden and uses only synthetic fixture bytes; no ROM, save, assets, audio or UI is loaded by the executable. Exact commands, tool/source/executable hashes and both receipts are in the portability report.

The implementation contract is Win32 pointer layout, aligned buffers and disabled strict aliasing. The Windows fill implementation is a supplied boundary validated by native observations, not a matching recovery of the ARM helper. Source-only ROM completion, a complete Windows game and Android device execution remain unproved. The new 164-byte source remains outside accepted cohort86 until a later integrator batch passes its gates.
