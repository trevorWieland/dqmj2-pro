# Independent initialization audit

The accepted cohort 80 identity snapshot contains 8,308 source paths. The diagnostic audit attempts 8,183 C/C++ paths; assembly paths are outside this frontend. It checks each selected source hash before and after analysis with the repository-local pinned NDK clang. The matching compiler remains CodeWarrior. No accepted source is edited.

Of 8,183 attempts, 8,158 parse successfully, 14 files emit 19 scalar-initialization diagnostics, and 25 fail frontend analysis. One failure is an audit language-flag limitation for a C++ file. The others involve vendor declarations, layout assertions or assembly syntax. They remain unsupported analysis cases, not clean results. Diagnostic counts are not function coverage or a general correctness verdict. A two-case independent calibration verifies both warning detection and a clean initialization case.

Run `python audit_selected_c_initialization_20261031.py` and `python calibrate_c_initialization_audit_20261031.py`. The reports are `evidence/verification/selected-c-initialization80-20261031.json` and `evidence/verification/c-initialization-audit-calibration-20261031.json`. Detailed compiler output stays under the report's explicit repository-local work directory. The frontend uses an ARM32 syntax/diagnostic target; it does not build or execute the game on Windows or Android.

Root reviewed three formatter files. Integer formatters 0x0201B8C8 and 0x0201BB14 initialize their base for every supported conversion in `diouxX`; their default-free switches do not define arbitrary invalid conversion bytes. This diagnostic does not establish a defect in their existing supported domain. In format core 0x0201CB74, distinct argument-option enum values select either long or long-long initialization, and the subsequent selection uses the same unchanged option field. The short/char narrowing arms belong to the long-initialized branch. There is no intervening call or source write to the format options between these decisions. These observations do not prove arbitrary aliasing or malformed-format callers safe and do not add new input restrictions.

Other findings are distributed by exclusive ownership. ARM7 reviews player-step predicate correlation, scheduler saturation, and two local payloads whose reserved bits require native/peripheral qualification. Save/core reviews the maximum accumulator and a possible argument-evaluation dependency at 0x0209BC38. Overlay work reviews kind/control domains and pointer/mode correlations in five files. Frozen sources stay unchanged; any confirmed correction requires a separate hypothesis and explicit regression migration. A warning is not evidence that every native path is erroneous, and a matching object is not evidence that C initialization or portable evaluation order is sound.

Separately, the original generated C61A4 draft correctly carried its remainder temporary. The later typed-width rewrite introduced an uninitialized later lookup argument; that unaccepted hypothesis is superseded by a distinct corrected hypothesis. The application handoff identifies its exact source hash and native boundary evidence. No accepted source or previously matched executable bytes were affected by that draft correction.
