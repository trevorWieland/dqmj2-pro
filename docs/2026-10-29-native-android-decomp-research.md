Begin with a C library and command-line executable for checksums and deterministic synthetic vectors. Add a thin JNI APK later. Avoid dependence on graphics, audio, real saves or assets. Run an independently built host fixture target when a host compiler is available. Android cross-compilation is compilation only: [CMake's cross-compilation runner property](https://cmake.org/cmake/help/latest/prop_tgt/CROSSCOMPILING_EMULATOR.html) exists for explicit target execution. Host CTest cannot be credited as execution of an AArch64 Android binary.

[Android's page-size guidance](https://developer.android.com/guide/practices/page-sizes) states that NDK r28+ defaults to 16-KB ELF alignment; AGP 8.5.1+ supports corresponding uncompressed-library packaging. Inspect every LOAD alignment for at least 2**14 and check the APK with zipalign -c -P 16 -v 4. Use runtime page size for OS allocation/mapping assumptions; DS buffer lengths have separate meanings. No 16-KB runtime was tested.

**Portable semantics.** [Android ABI documentation](https://developer.android.com/ndk/guides/abis) distinguishes 32-bit armeabi-v7a and AArch64 arm64-v8a conventions/layout, and notes removal of the old ARMv5/v6 ABI. Secondary ABI support depends on the system image. DS ARM9/ARM7 objects cannot simply become arm64-v8a application code.

Google's [64-bit porting guidance](https://developer.android.com/google/play/requirements/64-bit) covers pointer truncation, fixed-width types, prototypes, JNI pointer storage and architecture-specific assembly. Recommendation: represent DS addresses as 32-bit logical addresses or typed host objects with serialized offsets, explicitly resolving processor/module/overlay context. Never dereference 0x02000000 as an Android pointer or store a host pointer in a DS u32 field. Use uintptr_t for host-pointer round trips. Decode serialized bytes explicitly; review signed char, padding, bitfields, unaligned accesses, shifts, signed overflow and wide arithmetic.

The local [alternate-entry evidence](../evidence/entrypoints/main-20261029-div64-entry.json) demonstrates relevant edge cases. Native ARM entries 02025F1C and 02025F2C share a body but expose remainder/quotient behavior. Measured cases include numerator returns for denominator zero, INT64_MIN/-1 wrapping, and an INT32_MIN/-1 quotient of -2147483648 through the signed-32 fast path. Plain signed C division does not automatically preserve this behavior. Implement measured semantics or a verified input precondition. The entry report supplies no C or original-assembly credit.

Compare normalized values, bytes and state transitions across Windows oracle, host C and Android C; preserve ARM register/CPSR checks separately. The [Unicorn 2.1.4 API](https://github.com/unicorn-engine/unicorn/blob/2.1.4/include/unicorn/unicorn.h) provides instruction/time bounds and hooks. Require actual return, fresh state, bounded memory and diagnosed faults; successful API return alone is insufficient. Modeled dependencies and CPU fixtures do not prove complete DS hardware/timing behavior.

**Displays and controls.** [DisplayManager](https://developer.android.com/reference/android/hardware/display/DisplayManager) enumerates logical displays and provides a presentation category from API 17. Its built-in-display category is version 36.1 and cannot be assumed on Android 13. [Presentation](https://developer.android.com/reference/android/app/Presentation.html) requires an eligible output and can fail or be dismissed as display/policy conditions change. Current reference descriptions may differ on installed vendor firmware.

Recommendation: first probe actual displays, flags, modes, dimensions, presentation eligibility and physical assignment. Never assume top=0 and bottom=1. Render distinct grids, record touch routing and test pause/resume, rotation, lid/screen changes, focus transfer and surface recreation. If firmware exposes a composite output or restricts presentation, record it and choose an observed supported layout.

[SurfaceView](https://developer.android.com/reference/android/view/SurfaceView) requires valid-surface lifetime handling and synchronized callbacks. Manage both rendering outputs with explicit lifetime/thread/context ownership and decouple simulation timing from presentation callbacks. [GameActivity](https://developer.android.com/games/agdk/game-activity) bridges native lifecycle/input with SurfaceView rendering. It is a later shell option, unnecessary for initial arithmetic and insufficient to establish dual-display support.

[Controller guidance](https://developer.android.com/games/sdk/game-controller/controller-input) distinguishes buttons, axes, sources and focused-view delivery. Probe actual keycodes, axes, ranges and device descriptors; provide remapping and one gameplay input queue across windows. Test held buttons through focus transfer, touch-coordinate transforms, rotation/letterboxing and controller reconnects. Hall-stick marketing does not establish event codes or dead zones. Keep JNI small and obey thread-local JNIEnv ownership per [JNI tips](https://developer.android.com/ndk/guides/jni-tips).

A complete native port needs source replacements for DS graphics/VRAM, timers, DMA, interrupts, filesystem, IPC, ARM7 audio and used networking/services. Android threads/queues need ordering and lifetime contracts. Emulating original ARM7 code would not satisfy this native-port design. Screen/input demos do not establish complete platform replacement or playable functionality.

**Save and mechanics gates.** Prioritize checksum, bank selection, serialization/deserialization and accessors. Preserve every measured byte, including 40,560 semantically unknown save bytes, through round trips. Compare differing valid banks, invalid checksums, torn writes, chronology boundaries and malformed records with native behavior. Keep inferred meanings separate from proven predicates/callers.

[App-specific storage](https://developer.android.com/training/data-storage/app-specific) provides private files; the [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) provides user-selected import/export. Use disposable internal copies, retain the proven bank protocol and export separate files. [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile) is a local commit helper, not proof of native-bank or documents-provider failure equivalence. Verify all bytes, checksums, selected bank and interrupted-write results without overwriting the original save.
