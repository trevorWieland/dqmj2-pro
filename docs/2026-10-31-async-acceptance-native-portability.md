# Asynchronous acceptance native portability checks

The unchanged reconstructed 260-byte ARM9 asynchronous-acceptance C source and the already accepted 40-byte file-initializer C source now compile as native Windows x64 code. The Windows DLL executes all 1,440 synthetic model cases and returns successfully each time, with 648 explicitly supplied file-service completions. Checks cover the result word, all 84 context bytes, global error word, service order/scalar arguments, file-pointer relation, service-entry bytes and error state. The first malformed whole-C implementation, changing read-failure status two to three, is separately compiled into a second DLL and rejected at one-based case two. These tests add zero DS source coverage.

Reproduce with `python prepare_async_acceptance_ports_20261031.py`, using an absolute script path from another working directory. The [machine report](../evidence/portability/async-acceptance-windows-android-20261031.json) records compiler/linker hashes, commands, visible diagnostics, source hashes, Windows results, Android ELF details and bundle artifacts. The producer verifies every generator-source hash in the original native golden report before regenerating its model vectors.

The same source fixture compiles to an Android API33 AArch64 PIE with 16,384-byte load alignment. The private bundle is `build/android-async-acceptance-bundle-20261031/`: an executable, unchanged source snapshots, generated synthetic vectors and a manifest. No ROM, original executable image, game asset or save is included. Android device executions remain zero. No dual-screen integration, graphics, input, audio, actual storage, interrupts or whole-game behavior is tested.

The fixture uses explicitly four-byte-aligned byte-backed context storage and clang's no-strict-aliasing semantics. This is an implementation-qualified memory model, not proof of the original complete object declarations. Path and destination words remain opaque 32-bit fixture values. The provider file pointer is checked relative to the host context; ARM physical register values are not compared across architectures. The initializer's pointer-to-u32 return conversion still produces a visible warning and its value is unused by this caller. File open, seek and read initiation remain supplied boundaries, so this does not establish eventual asynchronous completion.

A future manually selected Android target can receive only `j2p_async_acceptance_arm64` through an existing ADB connection, run it from a disposable private test location and return its JSON result. A passing run must report 1,440 cases, 648 supplied calls and firstFailure zero, together with the device/OS/ABI and executable hash. Compiling or inspecting the ELF does not count as that run. No device or application state was changed here.
