# Native decimal-round helper source

Main ARM 0x0201C2EC/292 has ordinary C at `src/runtime/20261030_decimal_round/native_main_0201c2ec.c`. The canonical report is `evidence/matches/main-decimal-round-20261030.json`; its independently demonstrated base 2.0 O3/speed output contains 292 instruction bytes and no literals or external relocations. Genuine MWLD matches the complete canonical span. The source is accepted in cohort 64; see `docs/2026-10-30-cohort64-decimal-round-and-placement.md`.

Run `python match_main_decimal_round_20261030.py`, then `python validate_main_decimal_round_20261030.py`. The positive report reproduces identically from the parent working directory. It checks 1,336 original/source pairs / 2,672 actual returns, with independent full record and ordered-store models, isolated register/stack state, ARM/Thumb returns, varied interrupt/condition flags and no providers. The corpus uses 1..32 ASCII digits, signed retained-length extremes, exponent boundaries, ties, zeros and carry chains. Four separately compiled wrong sources fail both strict real linking and their independent behavior cases.

The sign, exponent, length and text field offsets are measured at 0, 2, 4 and 5. At zero retained digits, the tie branch reads the preceding length byte for parity. No general numeric-rounding contract is inferred from the low-level record transformation. Exponent carry wraps to the measured signed 16-bit representation. Padding, sign and unused text bytes are preserved unless an explicit modeled store changes them.

Invalid pointers, oversized physical records and arbitrary malformed digit bytes are unsupported. The fixed text capacity is a bounded record-layout assumption, not evidence about all native decimal producers. Original caller, decimal conversion, whole-module/source-only ROM and host-game execution are separate claims. The initial O2 body was 288 bytes; O3/O4 produce the complete 292. Failed compilation/profile probes remain under `evidence/attempts/` and receive zero source credit.
