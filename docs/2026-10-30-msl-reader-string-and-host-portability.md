# Runtime source references and early native portability checks

The reader callback at main ARM 0x0201D618/132 and string routines at 0x0201D6B8/200 and 0x0201D800/276 are independently compiled ordinary C hypotheses with complete native byte equality. They are queued after accepted cohort 57 and receive no new accepted module credit from this writeup. Each uses genuine MWLD and current measured boundaries. The reader matches pinned 2.0/base O2/speed; the two other routines require their separately demonstrated O3/speed settings. O4 also matches the comparison routine, without establishing one compiler setting for surrounding source units.

A public sibling-project MSL reference supplied useful control-flow and word-copy hypotheses. The two unmodified source files and CC0 repository license are preserved under `deps/references/zeldaret-tp-c8fa8c9e/`; the Git blobs and SHA-256 hashes are recorded in `evidence/research/20261030-msl-reader-and-string-reference-source.json`. Their pinned upstream locations are [scanf.c](https://github.com/zeldaret/tp/blob/c8fa8c9e2aab72cf4e5db0e5d1c84a9ea6ee6eb0/libs/PowerPC_EABI_Support/MSL/MSL_C/MSL_Common/Src/scanf.c) and [string.c](https://github.com/zeldaret/tp/blob/c8fa8c9e2aab72cf4e5db0e5d1c84a9ea6ee6eb0/libs/PowerPC_EABI_Support/MSL/MSL_C/MSL_Common/Src/string.c). These references are not compiler inputs or proof of an original SDK version. All three reconstructed sources compile independently without reference files, original executable bytes, assembly or fixed-register assignments.

The reader has 2,648 fresh-state pairs plus 24 persistent calls per image, requiring 5,344 actual native/C returns. Its model checks every byte, six full EOF-state words, full unget result words, all initial NZCV combinations, four cursor alignments, alias cases and opaque default-action pointers. It compares every general register, flags, complete RAM/stack, ordered accesses and actual return. Seven in-memory negative code controls reject wrong EOF state, read and unget cursor changes, signed byte return, truncated EOF query and nontermination. They grant no source or return credit.

The copy routine has 1,648 pairs / 3,296 actual returns; the comparison routine has 2,672 pairs / 5,344 actual returns. Independent byte-string models check unsigned comparison magnitude, complete data/canaries, stack and callee-saved restoration. Native/source CPU states and ordered accesses agree. Eight bytes per function are compiler-generated constant pools, guarded against execution and distinct from the 192/268 instruction bytes. The fixtures cover every byte, all four pointer alignments, matching and different alignment pairs, empty and 64-byte strings, mismatches and same-pointer cases. Padded synthetic RAM permits measured word reads up to three bytes after the terminator. Partial copy overlap, invalid pointers and unbounded strings remain unsupported.

Native compilation tests can begin with these isolated routines before the full game is recovered. `python compile_runtime_subset_20261030.py` uses the previously verified repository-local NDK r30 Clang/linker, pins their hashes, and emits a Windows x86_64 DLL plus an Android API 33 ARM64 shared library. The Windows DLL has no entry point or imported runtime libraries. `python verify_windows_runtime_subset_20261030.py` loads that locally built DLL and passes 6,154 public calls against independent value and memory models. Typed host structures use an eight-byte pointer and EOF at offset eight; the ARM9 structure has a four-byte pointer and EOF at offset four. The public state projection is compared without claiming equality of the two machine ABIs.

A repeat build from the parent directory produces identical Windows and Android binary hashes, with the Windows PE timestamp fixed at zero. Android ELF machine/type, exported functions, absence of needed shared libraries and minimum 16 KB load-segment alignment pass. Android execution is zero, and API/device compatibility and dual-screen rendering/input are untested. The first Windows build experiment remains separately recorded; current reproducible build, execution and cross-directory results are in `evidence/portability/`.

This is an early pure-runtime portability milestone. It adds no DS source credit, proves no source-only module or ROM, and does not run the game on Windows or Android. Application adapters and UI remain untouched.
