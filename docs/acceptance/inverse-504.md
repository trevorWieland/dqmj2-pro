## How to read this

The inverse set is **not** a list of lost sources. Every one of the 504 rows has a source
file recorded in the ledger's `sourceUnit`, and that file exists — which is why an
address-based definition check cannot see them: the unit is defined under a name that does
not carry the address.

The split matters:

* **A-strong (145 rows)** — the file carries the address in its name or body, so the row
  is a bookkeeping error and can be linked by name.
* **A-weak (359 rows)** — the recorded file exists but names neither the address nor the
  ledger symbol in its text. That is file-level evidence only. Either the unit is defined
  there under a third name, or the `sourceUnit` record itself is stale. These 359 are the
  ones that still need a per-row look; they are **not** confirmed renamed, and they are
  where any genuinely lost source would hide.

Buckets B (mention-only), C (data/assembly) and D (genuinely lost) are empty for this
ledger state: no inverse row lacks a recorded source unit, so nothing was found to be
missing outright. That is the reassuring half of the answer; the weak-A set is the honest
caveat on it.
