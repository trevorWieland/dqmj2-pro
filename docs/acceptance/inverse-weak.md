# Weak inverse rows: matched ledger rows whose source file does not name them

Generated by `ops/classify_weak_inverse.py`; the ledger is not edited.

A weak inverse row is a ledger row with `functionMatched: true` and a `sourceUnit`
whose file exists, but whose text contains neither the row address nor the ledger
symbol. This is the only place a lost or mis-attributed source can still hide.

| bucket | rows | bytes | meaning |
| --- | --- | --- | --- |
| PAIRED-CERTAIN | 0 | 0 | file names the row directly (empty by construction: such rows are not weak) |
| PAIRED-PROBABLE | 160 | 19982 | a definition measures to the row size (unique) or its name equals a ledger symbol |
| NO-DEFINITION | 153 | 13376 | no attributable definition: comments/externs only, or definitions with no unique match |
| DATA-OR-STUB | 61 | 16756 | header, data blob, or empty stub file |

## Method

1. Select `functionMatched: true` rows with an existing `sourceUnit` whose lowercased
   text contains neither the zero-padded address nor the ledger symbol.
2. Parse function definitions: C by brace-matched signature, assembly by `.global`
   symbols (fallback: non-`local_` labels).
3. Pair by evidence: compile the file with mwccarm 2.0/base (`-thumb` only for Thumb rows)
   or assemble `.s` with mwasmarm `-proc arm5TE`, read `STT_FUNC` sizes, and pair a
   unique definition whose measured size equals the row bytes. A definition whose name
   equals a ledger symbol also pairs (the file belongs to that row).
4. Files without an attributable definition become NO-DEFINITION; headers, data
   initialisers and empty stubs become DATA-OR-STUB.

No pairing is CERTAIN: by definition none of these files names its row.
