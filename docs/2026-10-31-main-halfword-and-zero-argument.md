# Halfword copying and an explicit zero argument

Two new main ARM units genuinely compile and link to their full 32-byte native ranges. Native qualification produces 768 recipe pairs, 1,536 actual top returns and 48 returning wrong-C controls. These are candidate source matches until module/ROM acceptance; neither original helper implementation receives extra credit.

At 02021274, source and destination advance by two physical bytes while copying halfwords through the first zero value. The generated signed-word/halfword pointer guesses had advanced the destination by four bytes. Correcting that stride first exposed a separate R3/IP allocation difference. Fifteen ordinary compiler/qualifier trials did not match; twelve of twenty-four ordinary declaration orders then produced complete matching C without register assignments, assembly, padding or instruction edits. The selected plain C has no added volatile qualifier.

The independent sequential model checks source reads, destination writes and destination readback, full backing pages, original destination return, source/destination aliasing, saved registers, SP, return mode, IRQ/FIQ control bits and both stack canaries. Supported layouts include disjoint, identical and selected overlapping arrays with bounded terminators. Forward overlaps that overwrite an upcoming terminator are excluded from this supported recipe set. No text encoding is identified.

At 0203CF7C, both lower calls consume an explicit zero word. The first return is tested for zero; a nonzero result triggers the second call, whose full word is returned. The old untyped second call erased its zero argument. Both helper identities are supplied without memory writes, so this proves the caller's arguments/control/return contract and does not establish their implementations or a heap-related meaning. The whole-C missing-argument control returns and fails the captured-call model on nonzero first results; zero-result cases remain positive.
