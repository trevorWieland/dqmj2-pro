# Native integer formatter source

Main ARM 0x0201B8C8/588 is reconstructed as ordinary C at `src/runtime/20261030_integer_formatter/native_main_0201b8c8.c`. Run `python match_main_integer_formatter_20261030.py` and `python validate_main_integer_formatter_20261030.py`. Demonstrated pinned 2.0/base O4/speed settings reproduce 584 instruction bytes plus the four-byte509 constant through the real MW linker. This source is pending a later complete module/ROM gate and is separate from currently accepted totals.

The pinned public MSL printf reference supplies the initial hypothesis. Its non-GCN long formatter contains a 64-bit minimum literal; this build uses 32-bit long. The original adaptation compiles to 592 bytes at O2/speed, and blindly dropping the condition yields 580. The measured 32-bit minimum condition yields 584 at O2, 588 with 571 same-offset bytes at O3, and all 588 bytes at O4. No instructions, relocations, addends or compiler objects are patched. The standalone source guards measured word/pointer/descriptor sizes, and surrounding-unit settings are not inferred.

A separate Python model renders signed decimal, unsigned decimal, octal and lower/upper hexadecimal magnitudes. It models zero precision, sign selection, alternate prefixes, zero filling, the 509 limit and each backwards byte store. There are 4,596 fresh cases / 9,192 actual original/source returns. The corpus covers full-word corners including 80000000/FFFFFFFF, three justification/sign options, alternate forms, four alignments, ignored descriptor bytes, selected field widths and every precision from -1 through 512. It compares all general registers/CPSR, bounded RAM/stack, ordered writes and unchanged original main bytes. The four-byte pool is guarded against execution.

The original unsigned divide helper at0x02026350 executes 52,720 actual returns across both images. Each observed return independently checks R0 quotient and R1 remainder against Python divmod, exact divisor and stack restoration. It receives zero additional source credit. There are no injected helper results or synthetic returns.

A null result is not an output-preservation guarantee: digits and the terminating zero may already have been written before the precision-limit failure. The independent model verifies those partial effects. Four separately compiled bad C sources are rejected by real linked-byte comparison and meaningful contracts: wrong decimal digits, wrong precision limit, wrong pointer result and nonreturning loop. The positive source stays unchanged.

Only six valid conversion selectors are supported by this helper model. Other selectors leave the source base uninitialized and are not presented as verified native error results. Invalid buffers, pointer aliases and arbitrary signed overflow in field/precision arithmetic remain outside the corpus. This ARM32 source does not establish a portable host formatter or full Windows/Android game execution.
