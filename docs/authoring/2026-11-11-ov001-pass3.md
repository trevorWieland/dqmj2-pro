# ov001 pass 3: forty-eight rows from the scan, state and timer neighbourhoods

Forty-eight unmatched `ov001` ARM rows are authored in
`src/ov001/p10_ov001_pass3`, 3,124 bytes total, byte- and relocation-exact
against `extract/arm9_overlays/ov001.bin` (base `0x021d7240`). Every row is
32-92 bytes and compiles under the module rule (`src/ov001/**`, ARM, profile
p003). The packet extends the pass-2 scan template and adds straight-line,
timer and state-family rows the ledger still showed unmatched.

`python ops/verify_ov001_pass3.py` recompiles every row with its resolved
source-unit rule, patches `R_ARM_PC24` with the `public_tools/repo_build.py`
formula, compares the whole measured extent, pins each relocation table,
proves every relocation target agrees with the image word, and runs one
whole-C negative control per function. It passes 48/48 with 48/48 controls.

## What made the rows match

1. **The pass-2 scan generalised.** The `+0x440` three-record do/while appears at
   three more widths: `0x0221b748`/`0x0221c11c` (80 B) replace the `+0x200`
   status block with a second service call and break to the shared `return 0`;
   `0x02223fe8` (56 B) keeps the scan but clears the output slot for each free
   record; `0x0221920c`/`0x02219dd8` (80 B) and `0x0221dca60` keep the scan and
   count accepted records instead of returning early. All keep `if (i == 2)
   return 1;` before the advance and put the exit test in the loop condition.
2. **A shared fail label is a branch, not a predicated move.** `0x02218178` and
   `0x0221dcfa0` only reproduce the image when both range tests jump to one
   trailing return (`goto fail`); two early `return 0;` statements make mwcc
   predicate the move and the bytes diverge.
3. **A result local controls the early-return rotation.** `0x021eaa3c`,
   `0x0221490c` and `0x0220b7b8` need `s32 result = 0;` (or `return 1;`) so mwcc
   materialises the constant before the test and predicates the pop instead of
   using `moveq` after the test.
4. **Declaration order decides r4/r5.** The two count scans differ only in which
   local is declared first: `0x0221920c` needs `count` before `i`, `0x02219dd8`
   needs `i` before `count`; `0x02213588` needs `u8 i` and a reloaded signed
   count.
5. **Keep literal data reloads direct.** The `0x0222b034`/`068`/`09c`/`0d0`
   family and `0x021e81d0` only match when the service target is named in the
   source: hoisting a `u8 *` local moves a literal load and changes the row. The
   `0x0221807c`/`180f4` strip family needs the fifth stack argument (`size`),
   which is why the image writes `str r0, [sp]` before the call.

## Family members

The eleven pass-2 family members (`0x0221a738`, `0x0221a7e4`, `0x0221b254`,
`0x0221b5e0`, `0x0221b834`, `0x0221b8b0`, `0x0221dcd4`, `0x0221e1c8`,
`0x0221e220`, `0x0221f0a4`, `0x0221f0f4`) are already present and byte-exact in
the pass-2 lane `src/ov001/p9_ov001_pass2`; `ops/verify_ov001_authoring_2.py`
reproduces 21/21 pass-2 rows including all eleven. They are not re-authored here
because the duplicate gate refuses a second definition of the same address. The
shared ledger still reads `functionMatched: false` for the whole pass-2 packet,
so promotion is a ledger reconciliation step for the coordinator.

## Result

* Attempted: 87 distinct fresh rows in the 20-92 byte window plus the 11 pass-2
  family contracts.
* Shipped: 48 functions, 3,124 bytes, every one exact with pinned relocations and
  a negative control.
* First authored form exact: 26 of 48 (54%); the other 22 converted after one to three
  neighbour-guided revisions.
* Template generalisation: yes. The `+0x440` scan covers three new widths and two
  new exit shapes (second-call test, accepted-count); the 56-byte `0x02223fe8`
  row is the same loop with a store instead of a return.
