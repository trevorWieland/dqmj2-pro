# ov006 sweep 2: the zero-shape remainder and the duplicate-pool class

The sweep-1 lane shipped 118 `ov006` rows and left two enumerated populations: 96
zero-shape transcribable singletons it had no room for, and 60 rows its transcriber
refused as carrying a duplicated non-address pool constant. This pass takes both.
**135 rows / 17,610 B** ship as transcribed `mwccarm` assembly, every row byte- and
relocation-exact against `extract/arm9_overlays/ov006.bin` (base `0x021d7240`), each
with one mutated-source negative control.

| form | rows | bytes |
| --- | --- | --- |
| zero-shape singletons (the sweep-1 plan complement) | 96 | 7,566 |
| duplicate-pool rows | 39 | 10,044 |
| **total** | **135** | **17,610** |

The lane is `src/ov006/g1_ov006_sweep2/{thumb,arm}/ov006/native_*.c`: 90 Thumb rows
(10,522 B) and 45 ARM rows (7,088 B). It is the first lane to resolve through a
`config/rules.d/` fragment (`config/rules.d/ov006-sweep2.json`, p033 Thumb / p003
ARM, both mwccarm 2.0/sp1p5 `89b2fc16`); the shared `config/source_units.json` is
untouched.

## The two populations

### 96 singletons (the sweep-1 complement)

Sweep-1 measured 443 genuinely unclaimed rows and 181 zero-shape transcribable
singletons; its plan kept the 85 largest by byte size. The remaining 96 (7,566 B:
55 Thumb, 41 ARM, 10-136 B each) are this pass's first population. The list is the
set difference of sweep-1's cached population (`analysis.json`,
`transcribable.json`, `partition.json`), regenerated deterministically by
`work/ov006-sweep2/make_plan2.py`; all 96 are clear in
`ops/unclaimed.py --check-addresses` against the pristine parent tree `08f06515`.

### 60 duplicate-pool rows: the refusal was half a false positive

Sweep-1 refused 60 rows with `duplicate non-address pool value`. That check
counted **loads**, not slots: `emit` built `occurrences[value]` from every
instruction that referenced a pool slot, so one slot loaded twice looked like two
slots. Measured on the image, the 60 split:

| shape | rows | bytes | disposition |
| --- | --- | --- | --- |
| two distinct slots hold the same value | 4 | 6,516 | 2 jump-table rows, 2 already the chunk lane's |
| one slot loaded twice | 56 | 29,316 | **39 shipped here**, 1 parked, 11 jump-table, 5 chunk lane |
| **total** | **60** | **35,832** | |

All four genuine duplicates hold address-like words (`0x0220cb88`, `0x0221c090`,
`0x0221c158`) and none is this lane's, so the 39 rows that ship needed **no new
alias spelling at all**: their correct source form is the plain numeric literal,
and the assembler's deduplication of one expression is exactly right.

The spelling that does keep two same-valued slots distinct was still found and
tested. `ops/probe_pool_aliases.py` compiles the same body under both modes with
the pinned compiler and reads the object back:

| spelling | pool words | relocations |
| --- | --- | --- |
| same numeric literal twice | 1 | 0 |
| two different spellings of the same literal (`0x11d` / `0x0000011d` / `(0x11d)`) | 1 | 0 |
| `native_const_0000011d` + `native_const2_0000011d` (two extern aliases) | **2** | 2 |
| alias + numeric literal | **2** | 1 |

Two distinct undefined symbols cannot be folded by the assembler, while every
numeric spelling of the same value folds into one slot. That is the winning
spelling for a genuine two-slot constant: per-slot alias symbols naming the
measured value (`native_const_<value>`, `native_const2_<value>`, ...). The
transcriber supports it behind `constant_aliases=True`; it is tested by the probe
but unused by the shipped rows because the class is empty in this population.
Duplicated **address-like** words already had the established `native_data2_`
spelling; four shipped rows use it (`0x021f2604`, `0x021f221c`, `0x021fe690`,
`0x02206080`).

`transcribe_chunk.emit` also gained `unique_pool_slots`, which counts distinct
slots instead of loads. It is opt-in so `ops/gen_ov006_sweep1.py` still recreates
the sweep-1 lane byte for byte: 53 sweep-1 rows reference one slot more than once
and the old counting chose different alias indices for them.

### One row parked

`0x021ebc2c` (2,584 B, Thumb) has a 12-word literal pool at +0x354 with code
continuing after it; two branches in the code land past the pool (one at +0x5c8).
mwcc places its own literal pool at the end of the function, so an inline-asm body
cannot reproduce an interleaved pool. The first generation truncated the row at the
first pool word and the control compile failed on a branch whose target is past the
16-bit range (`illegal operand`). The row is parked rather than guessed, and the
park is detected from the image (a branch into the inferred pool region), not from
the compile failure.

## C was attempted first, per row

Every transcribed row was compiled as C before it was transcribed, with the same
three plausible bodies rounds 7-9 used (field read, copy loop, block-struct copy):
**135 rows x 3 = 405 compilations, 0 exact**. The closest body is 10 bytes off
(field-read on `0x0220383c`), the median 90 and the mean 128.1 bytes off. The
per-row result is pinned in `ops/ov006_sweep2_cattempts.json`.

## Source-form rules these rows keep

1. **The body is the measured stream.** Instructions, the literal pool and every
   branch target are read from the image, never guessed.
2. **A duplicated value is counted per pool slot, not per load.** One slot loaded
   twice is one slot; a genuine duplicate is two slots.
3. **A genuine duplicate gets a distinct alias.** Address-like words use
   `native_data_`/`native_data2_`; a non-address constant would use
   `native_const_`/`native_const2_`. The alias name carries the measured value and
   the fixture pins the image word, so the value is verified, not assumed.
4. **A call is a named symbol, never a raw offset.**
5. **One negative control per row.**
6. **One address-named file per function.**
7. **Lane rules live in `config/rules.d/`, never in the shared array.**

## What remains

Of the round-8 443-row population: 118 shipped by sweep 1, 135 here, and 21
handled elsewhere (13 duplicate-pool jump-table rows, 7 chunk-lane rows, 1 parked
here). **169 rows / 38,352 B remain unshipped**: 56 write `pc` (the jump-table
class another lane owns), 9 are copy-pool shaped (the chunk lane's class, 6 of
which also write `pc`), and 110 are plain shaped rows that a later sweep can take.
The zero-shape singleton pool is now empty (181 = 85 + 96). Of sweep-1's six
parked family rows, the four `D4` rows ship here
(`0x021f2f60/2fc8/3030/309c`; their "duplicate" was the shared-slot false
positive) and the two `H2d` rows remain in the jump-table class.

## Unknowns

Byte identity establishes the code, not the meaning. Each file states its own
unknowns; the recurring ones are the block and field roles behind the
`native_fn_`/`native_data_` targets, the record layouts and strides the bodies
touch, the helper contracts, and which producer allocates the blocks the callee
chains fill. The `native_const_` alias mechanism is proven only by the synthetic
probe: no row in this population exercises it.
