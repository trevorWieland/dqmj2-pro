# main rows, batch 1: four small global-field functions

Four unmatched `main` rows are authored in `src/main/r1_main_small`, 132 bytes
total, byte- and relocation-exact against `extract/main.bin`. The lane needs its
own compiler rule: the module default (`p002`, mwccarm 2.0/sp1p5) does **not**
reproduce these rows, while `p001` on mwccarm 2.0/base does.

| `0x02083e08` | 32 | `native_main_02083e08.c` | `0x1c` ABS32 `native_data_021c72a0` | `0x021c72a0` |

| `0x020d13e0` | 36 | `native_main_020d13e0.c` | `0x1c` ABS32 `native_data_021d6bb4`, `0x20` ABS32 `native_data_021d6bcc` | `0x021d6bb4`, `0x021d6bcc` |

`python ops/verify_main_rows_1.py` recompiles every row with its resolved
source-unit rule, patches the relocations, compares the whole measured extent,
checks that each `R_ARM_ABS32` slot in the image holds exactly the object's target
(the literal/pool target is read from the image word, never from a symbol name),
and runs one negative control per function. It passes with 0 failures.

The repository build path independently measures the same thing: a
`public_tools/repo_build.py` run restricted to this lane reports
`matchedBytesByModule.main = 132` with no relocation outside the image.

## Candidate screen

`ledger/functions.jsonl` holds 1,015 unmatched `main` rows with measured bytes
(201 Thumb, 814 ARM). A mode-aware sweep of the measured bytes selected 147 rows
of 24-80 B with at most one call and at most two conditional branches.
`ops/check_duplicate.py --address-file` over all 147 reported one blocked address
(`0x20061ac`, matched only inside a one-line body of another function) and 146
clear, so no candidate collides with an existing `src/` definition.

## What the profile is

The ledger rows in this backlog carry `compilerFlags: null` and
`compilerSha256: null`, so the profile is evidence to be found, not read. Of the
5,448 matched `main` rows, 2,590 are `p001` on `7150fa4f` (mwccarm 2.0/base); in
the neighbourhood of the shipped rows the same pair accounts for 28 of 30 matched
rows at `0x02083c00..0x02084200` and 79 of 98 at `0x02044000..0x02046000`.
The lane therefore pins

```json
{"glob": "src/main/r1_main_small/**", "module": "main", "compilerFlags": "p001",
 "compilerSha256": "7150fa4f..."}
```

Both shipped rows in the `0x020d13xx` pair match under `p001` + 2.0/base only:
`p002` (the module default) produces a longer or differently scheduled body for
every one of the four.

## Two source-form rules the image enforces

1. **A global block is a byte array plus an offset macro.** The image keeps the
   *base* address in the literal pool and puts the field offset in the
   instruction (`ldr r1, =0x021c72a0; strb r1, [r1, #3]`). Writing
   `*(u8 *)(0x021c72a0 + 3)` makes mwcc fold base+offset into one literal
   (`0x021c72a3`), which changes the pool word and can never match. The accepted
   neighbours in `src/runtime/runtime07` use the same idiom, so the lane adopts it:
   `extern u8 native_data_<addr>[];` plus
   `M2C_FIELD(block, type, offset)`.
2. **Ordering across two blocks needs `volatile`.** `0x020d13e0` stores the mode
   byte at `0x021d6bb4` *before* reading the flag byte at `0x021d6bcc+0xd1`. With
   plain accesses mwcc hoists the flag read above the store; marking both accesses
   `volatile` pins the image's order. The same change plus a named temporary
   (`s8 temp_r0`) is what makes the row exact — `*flags |= 8` alone is five bytes
   off.

## Result

* Attempted: 22 distinct rows (24-80 B, at most one call).
* Shipped: 4 functions, 132 bytes, every one byte- and relocation-exact.
* First authored form exact: 0/22. Each shipped row converged on its second form;
  the first form was always missing one of the two rules above.

## Unknowns

Every row states its own in-source unknowns: the meaning of the `0x021c72a0`
block and its 1..15 range, the roles of the two copied blocks at
`0x021d53b4`/`0x021d53d4`, the mode byte at `0x021d6bb4`, and what flag bit 3 of
`0x021d6bcc+0xd1` enables. Byte identity establishes the code, not the gameplay
semantics.
