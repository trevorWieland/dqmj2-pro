# ov000 generation 1: forty-seven rows from five coarse skeletons and assembly emission

Forty-seven unmatched `ov000` ARM rows are authored in
`src/ov000/g1_ov000_gen1`, 3,752 bytes total, byte- and relocation-exact
against `extract/arm9_overlays/ov000.bin` (base `0x021d7240`):

| form | rows | bytes |
| --- | --- | --- |
| C instantiated from a donor template | 14 | 1,380 |
| mwccarm `asm` emitted from the measured stream | 33 | 2,372 |
| **total** | **47** | **3,752** |

The packet is a re-runnable generator, not forty-seven hand bodies.
`ops/gen_ov000_gen1.py --write` (re)creates every file from the ledger row and the
overlay image; `ops/verify_ov000_gen1.py` recompiles every row through its resolved
source-unit rule, pins each relocation table, checks each `R_ARM_ABS32` image word
against the object symbol plus addend, and runs one whole-source negative control
per row. It passes 47/47 with 47/47 controls and 160 pinned relocations
(127 branch, 33 `ABS32`).

## The skeletons that exist in the ov000 backlog

The row population is the 658 rows `ops/unclaimed.py --module ov000` calls
genuinely unclaimed from the source tree (405 high confidence, 253 medium). The
ledger flags 707 unmatched; the difference is 49 rows already defined in
`src/verified_assembly/20261111_asm_sweep1/ov000` and other accepted lanes.

The coarse-skeleton key is: **opcode + registers + transfer width fixed, every
immediate free, the trailing literal pool stripped.** Exact masked-word matching
finds almost nothing (687 clusters for 707 rows, largest 3). The coarse key finds
five real families of three or more rows:

| cluster | shape | rows | representative | C result |
| --- | --- | --- | --- | --- |
| F1 | 104 B table-driven stat update, `0x15` three-byte config rows | 5 | `0x021ebd88` | exact |
| F2 | 104 B 32-byte clear loop plus seven fixed calls | 4 | `0x021eb654` | exact |
| F3 | 144 B four-iteration scan with three nested guards | 3 | `0x02211f6c` | parked |
| F4 | 64 B signed-half narrowing plus two guard calls | 3 found / 2 shipped | `0x0221221c` | exact |
| F7 | 104/108 B strided record lookup and byte store | 3 | `0x02213e7c` | exact |

Five representatives were read from the measured stream. The rest were generated
by decoding the row's own parameters:

* **F1** — two pool bases, the one call target, the `0x15` bound, the `+3` config
  stride and the `+0xc` table stride all come from the row.
* **F2** — the buffer size, loop count, pool word and seven call targets; the
  last call's argument is the `mov r0, #2` before it.
* **F3** — the pool word, four call targets and the fixed `0xc` mode; the body
  never reproduced the original register rotation (`count` in `sb`, table in
  `r6`, `i` in `r7`, size in `r8`) across twenty-four declaration orders and two
  loop forms, so the cluster is parked rather than guessed at.
* **F4** — the two guard call targets; the signed narrowing needs `(s16)` casts
  on `u32` parameters. The representative `0x0221221c` is already defined in the
  pristine source tree (`src/overlays/...`), so the source-first screen refused it
  and only `0x0221225c` / `0x0221229c` ship. That is the screen doing its job: the
  ledger still calls the address unmatched, the tree does not.
* **F7** — the pool base, three call targets, the byte field offsets, the
  destination base, the word field and the shift; `0x02213e10` takes a fourth
  helper argument and narrows the shift to 4.

The 32 assembly rows are the rest of the small parked backlog. Each is the
measured instruction stream in mwccarm syntax: pool words become
`native_fn_<addr>` / `native_data_<addr>` symbols, calls become named symbols and
intra-row branches become labels. This is the round-6 rule applied at scale — the
rows that no C skeleton covers are transcribed, not guessed.

## First-try rate

| stage | first try | notes |
| --- | --- | --- |
| F1 representative | 1 body | `do/while` with `++i < 0x15`; 5/5 members first compile |
| F2 representative | 3 bodies | `for` rotated the loop and swapped `p`/`n`; `do/while` plus declaration order fixed it; 4/4 members |
| F4 representative | 2 bodies | `u32` parameters need explicit `(s16)` casts to emit the four narrowing instructions; 2/2 shipped members |
| F7 representative | 4 bodies | `ok` must be declared first and the store duplicated in both branches; 3/3 members |
| F3 representative | 6 bodies / 24 orders | no exact body; parked |
| C generation (after template) | **14/14** | every shipped family member matched on its first compile |
| asm emission | **33/33** | two generator spelling fixes (condition before width, backward-branch labels) changed no instruction |

The generator therefore did beat hand-authoring: zero function bodies were written
by hand, and after four template reads the remaining ten C rows and all
thirty-three assembly rows were first-compile exact. The five representatives
themselves took 1/3/2/4/0 attempts, which is exactly the "read a representative,
then instantiate" cost the round-6 technique predicts.

## Verification and gates

`python ops/verify_ov000_gen1.py` passes every row:

* patched text length and every byte equal to the image extent;
* relocation table equal to the pinned fixture
  (`ops/ov000_gen1_expectations.json`), 160 relocations including 33 `ABS32`
  pool words checked against the image word;
* one negative control per row compiles, differs from the image, and its
  differing byte offsets equal the pinned ones.

Other gates:

* `python public_tools/source_units.py --check` → `unresolved: 0` (the lane rules
  are `src/ov000/g1_ov000_gen1/**` at `p001` and
  `src/ov000/g1_ov000_gen1/asm/**` at `p001` + mwccarm 2.0/sp1p5).
* `ops/unclaimed.py --root <pristine ec661f64 checkout> --address-file ...`
  → 0 of the 47 addresses already defined under `src/`.
* no build artifact is tracked: objects are compiled under `build/` and a
  temporary directory, and `git status` contains only the generator, verifier,
  fixture, documentation, configuration rules and the address-named sources.

## Re-running the pass

```bash
python ops/gen_ov000_gen1.py --list        # the 47 planned rows and their form
python ops/gen_ov000_gen1.py --write       # regenerate every source
python ops/verify_ov000_gen1.py --record   # refresh the pinned fixture
python ops/verify_ov000_gen1.py            # the gate
python ops/test_gen_ov000_gen1.py          # generator spelling/decoding unit tests
```

`--only 0x021eb654 ...` restricts generation to named rows. The C templates live
in `C_TEMPLATES`; adding a row is one `(address, template)` entry plus, when the
row is a new family, one representative read. The ledger is an input: this packet
does not rewrite it, so the 47 rows are ready for the usual guarded ledger
application separately.
