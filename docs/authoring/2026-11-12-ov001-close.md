The generator emitted all 671 files with no hand editing, but the first verification

per-row edit**. The 307 rows that never grew confirm the build choice changes nothing
about the emitted instruction stream; it only removes the veneer.

## 42 rows carry an in-row ARM dispatch table, and all 42 are instruction streams

`ops/scan_jump_tables.py --module ov001 --unclaimed ...` proves the ARM
`add pc, pc, rN, lsl #2` dispatch in **42** rows (1,232 table bytes, 308 entries, 4-38
per table) and resolves each table address from the instruction semantics.

Those 42 rows ship as instruction streams on purpose: every entry of an ARM dispatch
table is a **branch word** (`b target`, `0x0a......`), i.e. an instruction the
dispatch executes, not data the body reads. The scanner only accepts a table whose
entries are branch words that target the row, so "table entry" and "executed branch"
are the same object here. That is the difference from the ov006 round, where the one
`dcd`-carrier row's table was *data* between code runs; there is no such extent in this
population.

The data screen agrees: across the 671 rows the highest share of image-pointer words in
any extent is 15% (`0x02216554`, 7 of 46 words), and those words are the literal pool,
which the relocations already pin. No row's extent is a pointer array, a byte table or
a halfword table, so no `dcd`/`.hword` carrier row exists to ship. The screen is

## Source-form rules these rows keep

1. **The body is the measured stream.** Instructions, the literal pool and every
   branch target are read from the image, never guessed.
2. **A pool word is a relocation, not a constant.** A word that names something in the
   image is a `native_fn_`/`native_data_` symbol; a magic constant stays numeric.
3. **A duplicated value is counted per pool slot, not per load**, and a genuine
   duplicate gets a distinct alias.
4. **A call is a named symbol, never a raw offset.**
5. **One negative control per row.**
6. **One address-named file per function**, with the measured shape, the pool words,
   the in-row branches, the tests and the unknowns in the header.
7. **Lane rules live in `config/rules.d/`, never in the shared array.**

Every file states its own. The recurring ones are the block and field roles behind the
`native_fn_`/`native_data_` targets, the record layouts and strides the bodies touch,
the helper contracts, and which producer allocates the blocks the callee chains fill.
The 42 in-row dispatch tables' entries are measured branch words whose meaning is not
recovered: the dispatch range is measured, the case semantics are not.
