# assembly sweep 1: the round-5 rule applied to fifty-eight parked rows

Fifty-eight unmatched rows (3,556 bytes) are reconstructed in the repository's
verified-assembly form: one `.c` translation unit per function whose body is the
measured instruction stream written as an mwccarm `asm` function. Twenty-two rows
are `main` (1,008 B) and thirty-six are `ov000` (2,548 B). Every row is byte- and
relocation-exact against its module image, with one negative control per row.

The rule is the one proven in round 5 (`docs/authoring/2026-11-11-main-families.md`):
when a row resists C across many bodies, transcribe the measured stream instead of
guessing another source form. This pass applied it to the classes that round 5
named as the next targets.

The three named classes (if-conversion, aggregate copy, scheduling and control flow)
account for 37 rows / 2,340 B. The remaining 21 rows are the same rule applied to the
parked allocation and instruction-form failures; they are reported separately rather
than folded into class 3, because their recorded C diff is not a scheduling shape.

Of the 58 shipped rows, **51 carry a recorded C diff from an earlier lane** in this
repository (6 if-conversion, 15 scheduling, 9 control-flow, 18 allocation, 3
instruction-form). The other 7 are aggregate-copy rows of the class round 5 closed
with 20 distinct C bodies at 0 matches. The assembly lens therefore converted 51 rows
whose C failure is documented plus 7 rows whose shape class C is closed: 58 rows that
C had not matched, at 0 further C attempts. The parked C record it replaces is 22
`main` failures, 35 `ov000` failures, and round 5's 40 family-A plus 20 family-B bodies.

## Method

1. **Candidate screen, source first.** `ops/unclaimed.py --all` ranked every ledger row
   with measured bytes; `ops/unclaimed.py --check-addresses` over the final 58 reported
   `0 already defined under src/` against a pristine `682d8084` checkout. Candidates came
   from the one-line failure tables in `docs/authoring/*.md` and from an ARM shape scan of
   the still-unclaimed rows for writeback block transfers and predicated block moves.
2. **Decode from the image.** Each row was disassembled from its measured extent; every
   literal-pool slot was read out of the image and every branch target resolved against
   the image, not against the compiler's placeholder.
3. **Transcribe, do not paraphrase.** The body is the measured instruction stream in
   Metrowerks syntax. A pool word that names an address is a symbol (`native_data_<addr>`,
   `native_fn_<addr>`, `+1` for a Thumb code pointer), so the object carries a real
   `R_ARM_ABS32`; a call is a named `native_fn_<addr>`; a second pool slot holding the same
   value gets a distinct alias symbol so the original duplicate pool word is preserved.
4. **Compile with the row's rule and compare the whole extent.**
   `ops/verify_asm_sweep1.py` resolves each file through `config/source_units.json`,
   patches the relocations the way `whole_image_link` does, compares every byte, checks
   every `R_ARM_ABS32` image word against the object symbol plus addend, and runs one
   mutated-instruction negative control per row.

## First-try rate

All 58 shipped bodies matched the image on their first compiled transcription. The
generator needed spelling fixes before nine of them would assemble at all, and none of
those fixes changed an instruction:

* standalone shift mnemonics (`lsl r0, r2, #0x19`) are not accepted; they must be spelled
  `mov r0, r2, lsl #0x19` (three rows);
* conditional halfword/signed loads take the condition before the width (`ldrleh`,
  `strleh`, `ldrgtsb`), unlike capstone's `ldrhle`/`strhle`/`ldrsbgt` (three rows);
* `smlal` must not be read as `sml` + `al` by the condition splitter (one row);
* `push`/`pop` must be written `stmdb sp!`/`ldmia sp!` (all rows with a frame);
* the assembler deduplicates a literal pool expression that names the same symbol twice,
  so a pool slot loaded twice is emitted once and two slots with the same value need an
  alias symbol (eight rows, +0x4 B each when missed).

Measured body revisions after the generator was correct: **0**. The C-attempt counts the
parked rows already carry (22 documented `main` failures and 35 `ov000` failures, plus
round 5's 40 family-A and 20 family-B C bodies) are the evidence that these rows had
already resisted C in this repository.

## Source-form rules these rows keep

1. **An `asm` function body is the reconstruction form for a row that resists C.** The
   build compiles it through the normal C rule; no new build path exists.
2. **A pool word is a relocation, not a constant.** `ldr rN, =native_data_<addr>` emits
   `R_ARM_ABS32`; the verifier proves the image word equals the symbol address plus addend.
3. **A call is a named symbol, never a raw offset.** `bl native_fn_<addr>` pins the callee
   by an address-bearing name; the verifier patches it the way the linker would.
4. **One negative control per row.** The first mutable instruction is changed (a register
   substitution, always encodable) and the control must differ from the image.
5. **One address-named file per function.** The lane resolves through two new rules under
   `src/verified_assembly/20261111_asm_sweep1/{main,ov000}/**`, both `p001` on
   `89b2fc16` (mwccarm 2.0/sp1p5), matching the accepted verified-assembly neighbours.

## Unknowns

Byte identity establishes the code, not the meaning. Every source file states its own
unknowns; the recurring ones are the block and field roles behind the `native_data_`
targets, the record layouts and strides (0x34, 0x16, 0xc4, 0x140), the callee contracts
of the `native_fn_` targets, and which producer clears the status words the guarded rows
poll.
