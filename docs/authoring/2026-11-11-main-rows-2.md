# main rows, batch 2: thirty global-state and record functions

Thirty unmatched `main` rows are authored in two lane directories, **1,888 bytes
total**, byte- and relocation-exact against `extract/arm9/arm9.bin`. This is the
second dedicated main-module pass; the first shipped four rows (132 bytes) after
twenty-two attempts.

| outcome | batch 1 | batch 2 |

## Method: neighbours first, then the form

Every row started from the accepted corpus, not from a guess:

1. **Cluster the unmatched row** by its measured instruction shape (literal-pool
   words masked, so a pool address never changes a shape signature). Where an
   accepted row shares the shape, its source is the donor; where no accepted row
   shares it, the nearest accepted sources in the same address region were read
   before writing.
2. **Derive the compiler from the matched neighbours.** Around `0x02083c00` and
   the other regions the accepted rows are overwhelmingly `p001` on mwccarm
   2.0/base (`7150fa4f`), so `src/main/r1_main_small` keeps that rule.
3. **Write, compile, compare the whole extent, and read the disassembly diff**
   rather than guessing again. Thirteen rows needed exactly one evidence-driven
   revision; the clean single-cause revisions are listed below.

### Why a second rule exists

The six large command/record rows (`0x0204dd18`, `0x020501f4`, `0x02054608`,
`0x0204ed3c`, `0x02052720`, `0x0204c8d4`) are reproduced only by the **module
default** `p002` on mwccarm 2.0/sp1p5 (`89b2fc16`). The discriminating instruction
is the record-index multiply: 2.0/base emits `smulbb`, 2.0/sp1p5 emits `mul`, and
the image holds `mul` while every other byte of the shape agrees. A profile sweep
over six profiles x six installed builds confirmed only `89b2fc16` reproduces
them. They live in `src/main/r2_main_large` under a `p002` rule rather than being
forced into the p001 lane.

## Source-form rules the image enforces

1. **A global block is a byte array plus an offset macro.** The pool word is the
   block base and the field offset stays in the instruction. `M2C_FIELD` on
   `extern u8 native_data_<addr>[]` preserves that; folding base+offset into one
   literal changes the pool word and can never match. The same rule applies to a
   *table*: the element index appears in the load, not in the literal.
2. **`volatile` pins ordering and load order.** `0x0203915c` loads `+0x7c` then
   `+0x80` and stores afterwards; plain loads are reordered and merged into
   `stm`. Marking the two loads volatile reproduces the image exactly.
3. **A named temporary pins operand order and register roles.** `0x02040534`
   stores `(old | mask) ^ mask`; without a temp mwcc emits `eor r2, r0, r2`
   (operands swapped). `0x020455ac` needs a `u32` temp so the base, the shifted
   bit and the halfword land in the image's registers. Both rows were failures
   in batch 1 for exactly these reasons.
4. **A pointer local fixes which register holds a block base.** `0x0204448c`
   increments a byte counter and returns the new value zero-extended. A direct
   `M2C_FIELD` expression puts the base in `r1`; `u8 *p = native_data_...` puts it
   in `r0`, which is what the image does.
5. **A one-bit flag is a bitfield read, not a mask.** `0x020191fc` holds
   `lsl #31; lsr #31`; `x & 1` compiles to `and`, `(x << 31) >> 31` to
   `lsl/asr`. An `unsigned int flag : 1` member produces the image's logical shift
   pair.
6. **ABS32 patching copies the measured image word.** The verifier therefore
   checks every object relocation target *against the image word* explicitly, and
   a negative control cannot be a pool-symbol swap: it must change the instruction
   stream (operator swap or a return-expression mutation).

## Verification

`python ops/verify_main_rows_2.py` recompiles all thirty rows with the rule their
directory resolves to, patches the relocations the way `repo_build` does, and
compares the whole measured extent:

* object relocation table equals the pinned table (offset, kind, symbol, addend),
  including linker-resolved compiler helpers (`_fflt`, `_ffix`, ...), which are
  decoded from the measured call site and pinned as `native_fn_<target>`;
* every `R_ARM_ABS32` image word equals the object's relocation target, so a pool
  word is checked against the image word, never a symbol name;
* one whole-C negative control per row compiles and differs from the image at a
  pinned offset list.

Result: **30 rows, 1,888 bytes, 0 failures.** `public_tools/source_units.py
--check` reports `unresolved: 0`. `ops/check_duplicate.py` over all thirty
addresses against a pristine `3b194b526` checkout reports `30 addresses, 0 already
defined under src/`. No build artifacts are added; `work/` stays ignored.

## Unknowns

Every row states its own unknowns in-source. Byte identity establishes the code,
not the gameplay meaning: block ownership and field semantics for the
`0x021c72a0`, `0x020edd0c`, `0x020f6054`, `0x020f69c4`, `0x020f6ae4`,
`0x020f4c44`, `0x021c9600`, `0x021c6e10`, `0x020d940c`, `0x020e2cb0`,
`0x020edf90` and `0x027ffc30` blocks; the record and bank layout behind the
fixed-point publish family; why the counter at `0x020edf84+4` is polled; and the
caller contract of each tail-call thunk.
